# 2026-10-15：门户与采集仓库复核

## 范围与结果

本轮复查 Kenxu 1.7.2 的精简个人中心、SG 优先响应图和宽屏节点布局，并核对两个 GitHub 默认分支及线上采集状态。起点分别为 `DonsonHH/kenxu` 的 `0758c9c`（main）与本仓库的 `abd6917`（master），两者本地工作区均干净且与远端相同。

发现并修正一项文档一致性问题：本仓库 README 与计量说明仍将 1.5.0 的按分钟关联网站描述为当前实现，并将已验收的 flow 部署称为下一阶段。现明确旧算法已移除、原生总账与连接分类不叠加、用户最近 IP 的展示与查询权限，以及固定核心的维护和回退边界。没有因此改动任何线上代码、路由、账号或账本，也未发布新的门户版本。

## 验证结果

- 门户 59 项 Node 测试、完整 11 个隔离 Edge 浏览器脚本通过；本仓库 25 项 Python 测试通过。重新构建门户未产生生成文件差异，生产依赖审计未发现已知漏洞。
- 浏览器复核个人中心仅一张卡片、最近 IP 后显示归属估算、只补查这一条且缓存命中不重复外查；旧历史来源栏目不再被请求。会话失效、迟到 401 和跨账号状态清空回归通过。
- 刻意乱序的测试节点在图表中按 SG1／SG2／SG3／US1／US2／其他显示，延迟与对应节点不串线。1440／1920／2560／3840 CSS 像素下六张卡片同排，1280／768／390 保持可读换行，无横向溢出；已人工查看本轮生成的桌面和手机深色截图，均为虚构测试数据。
- 生产门户仍为 1.7.2，门户、连接检测和 Tunnel 服务均 active。公开 HTTPS 的七项脚本／样式／国旗资源哈希与本地一致；HTML 严格去除唯一、已识别的 Cloudflare analytics 附加脚本后，应用正文逐字一致。HTML 为 `no-store, private`，未改 CSP 或 Cloudflare 配置。
- 六位可用用户的本人来源权限、管理端独占目标详情、五个采集器／六条逻辑线路覆盖检查通过。未为验收调用生产 IPinfo 补查，也未读取或展示真实来源地址、网站和凭据。
- 18 份实际 Clash／Stash／Shadowrocket 订阅响应体与已有基线相同；账号、授权、凭据、规则、设置、密钥、原账本和分类历史字节未被改写。短期诊断会话已清理，不替换既有用户登录。
- 五台节点均通过当前 `tools/review_flow.py` 的只读检查：原生与观察累计夹取核对一致、两类上传队列排空、SQLite 完整、观察 socket 私有、API 仅回环、服务 active，二进制 SHA-256 与既有验收版本一致。初次快照中的两处单条在途报告正常清空，未删除或重置队列。

## 边界

本轮是源码、回归与短时线上复核，不是任意协议／浏览器／真机或长时间 soak 的全面证明。没有重新构建或切换 Xray 核心；固定源码与产物的重建证据仍以 [flow 验收记录](kenxu-flow-rollout.md) 为准。硬崩溃尚未落盘窗口、历史无法追溯的目标、IP 地区估算误差和隐藏直连备用未计量的限制仍然存在。

两个 GitHub 仓库的公开 Actions 运行记录均为零；本轮通过的是上述本地与线上检查，不宣称已获得 GitHub CI 绿灯。门户源码未发现需要修正的问题，因此不创建空提交或为文档修正重启线上服务。本仓库仅提交本轮文档修正与复核记录。
