# Kenxu 逐连接分类计量：落地与验收

2026-10-15。固定上游 Xray v26.3.27，commit `d2758a023cd7f4174a5a5fa4ff66e487d4342ba0`，Go 1.26.9。

分类统计含目标 TLS／HTTP 自身字节，不是文件净大小或 Azure 网络账单；没有解密 HTTPS。原总账独立保留，不能把分类再加到账本。历史没有逐连接信息的日期不回填网站去向。JP／China 隐藏直连仍不计量。

## 实现与许可

- `core/xray-26.3.27.patch`：保留具体 writer 类型和原生计数，逐逻辑连接绑定观察；Vision 的原生 splice 按 1 MiB 或约一秒提交进度，非观察账号保持原路径。首次并发注册计数器失败时重新获取已注册对象，防止一个新连接完全没有计数器。
- `core/kenxuflow`：Unix socket 0600、目录 0700；256 条不可变批次、epoch/seq、落盘后 ACK、短连接终值、UTC 分钟归属、来源迁移、容量超限降级 unknown。正常关闭时结束被观察传输并 fsync 尾部批次。
- `files/kenxu_flow.py`：SQLite 独立队列，按数值顺序重放关闭检查点；门户故障不阻塞从核心落盘。重试和重复 ACK 不丢失、不重复添加原账本。超 30 天的主机和 IP 脱敏，保留字节和幂等信息。
- 上游改动和新模块采用 MPL-2.0，完整许可位于 `core/LICENSE`；发布修改版二进制时必须同时提供对应固定源码／补丁，不能只发布闭源产物。

构建使用已检出固定提交的上游仓库，不调用 latest 安装器：

```sh
bash core/build.sh /absolute/path/to/pinned-Xray-core /absolute/path/to/xray-kenxu-amd64 amd64
```

`KENXU_RACE_CHECK=1` 额外运行 race 检测，需要本机 C 编译器。五台现有 VPS 为 amd64；arm64 构建接口有支持，但没有经过同样的节点验收，不据此直接部署 ARM 服务器。

仓库补丁已从干净固定提交重新应用、测试并重建，产物 SHA-256 与五台线上核心逐字节一致。`build.sh` 同时固定 Git 源文件导出换行，再规范化补丁触及的 Go 文件；这是为了再现已验收输入，因为 Go build ID 也受源文件字节影响，不是功能性修改。

## 隔离校准

在 US2 使用**独立网络命名空间**，只绑定其回环端口，临时虚构用户与证书，不读取真实配置、不开放外部端口：

```sh
sudo unshare --net sh -c 'ip link set lo up; python3 tools/calibrate_suite.py --candidate /absolute/path/to/xray-kenxu-amd64 --output /private/path/calibration.json'
```

应先复制工具到同目录并在固定环境运行，不能把上面示例路径原样当作现成安装路径。实际校准覆盖：两用户／两目标 raw TCP、1 万短连接暂停采集、TLS 1.3 独立 socket 字节、Reality＋Vision 长连接进度、UDP、TCP MUX、多目标 XUDP、换入口 IP、正常 SIGTERM 尾部落盘、幂等读取／ACK。Go 另测并发、分钟与北京时间跨月边界、容量和保留期；Python／门户测试覆盖断网耐久重试、权限和原账本不变。

原版实测复现 Vision 长连接关闭后才大笔提交计数，以及首次并发注册计数器竞争。前者可能导致时间分布延后，后者会漏算；**都不能证明 hdc 的全部历史大流量来自这些原因，不能因此统一删除／减半历史账本。**

小型 HTTPS 另做三点核对：应用 SSL MemoryBIO、独立目标 socket、节点原生／观察值。并发快速收尾时，原版与候选都可在目标端多转发若干 24 字节尾部记录，应用 SSL 输入不含它们；目标 socket、原生计数与逐连接观察仍严格相等。此类额外转发属于目前观察点的真实字节，不根据应用输入强制扣掉。公网试点下载与应用 wire 相等，上传的少量此类尾部差异单独标明，不能把它描述成与应用输入逐字节相等，更不能把数 GB 的异常归因于这些尾部。

最终候选的 SHA-256：`2f01e0a2441072bce82eef72dfe1c2df7b15767bd08fc9910595d9a7a8a2915b`。独立字节校准全部通过。性能在不并行上传的五组交替样本上复测，全部首字节样本合并 p95 为原版 6.485 ms、新版 8.048 ms；核心 CPU 中位数 0.92→0.99 s（+7.6%），传输耗时中位数 2.811→2.709 s，峰值内存中位数 34.19→33.71 MB。它是该硬件／夹具结果，不是公网线路延迟或任意负载的保证。

## 生产门槛与回退

默认 `kenxu_flow_enabled=false`。`kenxu_flow_shadow.yml` 需要显式校准标记；非空 `kenxu_flow_users` 先做 hdc 单节点试点；空列表全量需要 `kenxu_flow_pilot_reviewed=true`。始终 `serial: 1`、任何失败停止后续节点。

`tools/deploy_flow.py` 预校验固定哈希／版本、服务用户与端口唯一归属；备份配置、原服务片段、采集代码和脱敏队列快照。排空原生计数后停止新入站、关闭该代理端口上的旧连接，再取最后计数；只切换 systemd ExecStart 和新增采集设置，**不重建凭据／路由**。首次真实切换曾因 umask 使代码目录不可遍历，启动检查拒绝并成功回退；已修复目录权限并重新验证。

失败恢复旧代码和服务片段，不用旧数据库覆盖新字节。备份仅用于诊断／人工恢复，原动态队列始终向前补报。普通 `kenxu_meter.yml` 保留 flow 设置；`software.yml` 拒绝对固定核心运行未验收的 latest 安装流程。

## 已知边界

- SIGKILL、断电或进程硬崩溃无法运行尾部钩子，最多会损失尚未落盘的观察窗口。页面断点／覆盖时间重新开始，不宣称零丢失。
- “正常 SIGTERM 尾部通过”不等于任意崩溃耐久；内存上限后 unknown 的时间桶可能变粗，不把它强行分给网站。
- 目标可能是 IP／共享 CDN；按可确定主域名汇总，不反向猜测应用、URL 或用户行为。
- 底层 XUDP 全局 ID 的安全属性属于上游协议；本补丁对观察账号的重绑定检查认证身份，不替代协议栈整体安全审计。
- 校准没有覆盖所有协议、每种客户端／WebSocket 应用组合，也没有做长时间 soak；部署后仍需观察队列、原生与观察累计守恒及服务稳定性。
